## 3. 有意的载体差异（行为一致或已获批）

1. **菜单**：Tk 原生 `tk_popup` → 自绘 HTML 菜单（白底圆角阴影）。菜单项、顺序、sep、点击语义逐项一致；视觉是 0.2.7 视觉语言的自然延伸（同 Phase 0 批准的设计方向）。标题栏那一份已于 0.4.0 取消（§3-10），现在只剩列表空白 / 行 / 面板三处，外加 0.4.2 的顶栏文件菜单下拉（§3-16，开合状态挂在第一枚图标上）。
2. **主窗口两态（ADR 0004，0.4.0）**：Tk 0.2.7 的 📌 是「贴桌面 / 悬浮置顶」，且贴桌面时任务栏没有入口。用户 2026-11-13 定稿改为「固定在桌面 / 普通窗口」：固定在桌面 = 桌面图标之上、所有应用窗口之下，任务栏与 Alt+Tab 里都没有它（`WS_EX_TOOLWINDOW` + `ITaskbarList::DeleteTab`）；普通窗口 = 正常 z 序、任务栏有图标、Alt+Tab 里有它，点任务栏图标就能加待办；默认普通窗口。置顶功能整体下线（两种模式都不 topmost），新增常驻托盘（左键唤回普通窗口，右键菜单切模式/退出），面板仍不进任务栏且保持 topmost。切换两态就地落样式、不 hide/show（窗口不闪），任务栏与 Alt+Tab 归属由 `ITaskbarList` + `SWP_FRAMECHANGED` 让 shell 重算（[#8](https://github.com/zwxdogs/desktop-todo/issues/8)）；两态都显式对齐 DWM 圆角偏好，工具窗（固定在桌面）也要系统圆角与外阴影，两态看起来是同一个窗口（[#9](https://github.com/zwxdogs/desktop-todo/issues/9)）。
3. **拖动/缩放手势**：Tk 手动 geometry → 系统原生拖动/resize。手感更好；位置尺寸记账经 Moved/Resized → dirty_config → ≤1s 内落盘（Tk 是 release 时写）。
4. **跨窗面板通信**：Tk 直接调 self 方法 → main↔panel 事件。面板编辑提交瞬间有一次旧值→新值的重渲染（Tk 是同步刷新），≤1 帧。
5. **测试日志**：testing 模式写 `widget.log`（saved/loaded/panel/undo 等状态迁移，与 Tk 0.2.7 的 widget.log 同层级）；生产模式不写日志文件。调试期探针（click trace、按钮 client 坐标、toggle 栈、client_to_screen）已全部删除。
6. **拖动排序（0.4.0 新增，Tk 0.2.7 没有）**：主窗口里分组标题与顶层待办可拖（行右缘把手，悬停现身），整块搬：待办带走子树、分组带走整组，缩进原样；面板两栏各自排序（子待办/备注互不越栏，指针移出本栏即无落点）。落点只有整块边界（行间插入线 #4A8FE2，从缩进位画到行右缘），每次落点一条撤销记录，落回原处不写文件。两条边界规则写在 md.canMove 里：「第一个分组标题之前永远不设落点」「分组只落在另一组的标题之前或文件末尾」（否则会静默并组）；指针停进上下 24px 连续自动滚动。
7. **主窗口不渲染备注（0.4.0）**：备注只在详情面板出现；顶格备注行静默隐藏，文件字节保真、不迁移、不可编辑（用户 m00066/m00070 选定的甲案）。非待办/非备注的其它行（分不清类型的纯文本行）仍按 0.3.0 原样渲染，不隐藏。
8. **跨窗口拖拽没做（载体限制）**：主窗口↔面板之间不能拖。WebView2 上 HTML5 DnD 跨窗口会被 wry 的 IDropTarget 吃掉（非文件载荷回 DROPEFFECT_NONE，tauri#15138 not planned），pointer 拖拽又跨不了窗口；0.4.0 只做各窗口内的排序。
9. **测试模式不写 config.json（ADR 0004 期间新增）**：`DesktopTodo.exe <file> <dock|float>` 本来就从不读 config.json，但以前退出时照样把测试文件与测试窗口尺寸写进 exe 同目录的 config.json——跑一次探针就会把用户真实部署的配置改掉（2026-11-13 实测踩到，部署实例一度指向临时测试文件）。现在 testing 分支下 `write_config` 直接返回并记一行 `test mode: config.json not written`。
10. **标题栏右键菜单取消，改顶栏常驻图标（0.4.0，[#3](https://github.com/zwxdogs/desktop-todo/issues/3)）**：原「右键标题栏 → 更换文件… / 打开文件位置 / 退出」整块删除，前两项改为顶栏两个常驻图标（内联单色 SVG，13px，热区 30×26，tooltip 走 `title`），中间 1px 分组竖线（`pointer-events: none`，穿透后等同点标题栏空白可拖窗）；右键标题栏现在什么也不发生。原因不是审美：Tauri 注入的 `window/scripts/drag.js` 在 document **冒泡**期注册 mousedown，命中 `data-tauri-drag-region` 时 `preventDefault + stopImmediatePropagation + start_dragging`，页面脚本冒泡期注册的"点菜单外面关掉"永远收不到——"菜单弹出后点标题栏关不掉"在该载体下修不好；常驻图标没有开合状态，直接绕开整类问题（0.4.2 的文件菜单下拉重新引入开合，改用捕获期 `pointerdown` 绕开同一条被吞的路径，§3-16）。退出只剩顶栏 ✕（列表空白右键菜单里那一项后来也删了，§3-14）。顺带：最小内宽 260 → 300（顶栏多了两个按钮，260 会把标题挤没），并删掉 `tauri.conf.json` 里主窗口 `create: false` 下不生效的 `minWidth/minHeight`；标题截断时悬停由 `title` 属性给出完整文件名。
11. **点标题栏提交内联编辑（0.4.0，[#4](https://github.com/zwxdogs/desktop-todo/issues/4)）**：用户可见行为与 Tk 一致（`todo.pyw:912-925` 就是提交），差别在实现——`app.js` 的"点编辑框外面提交"与"点菜单外关闭"、`panel.js` 的同款关菜单三条 document mousedown 改到**捕获阶段**。捕获先于注入脚本的冒泡监听，不再被 `preventDefault` 连带打断 input 的 blur（原来两者都会让编辑停在未提交状态）。
12. **＋ 从「末尾加待办」改成「新建待办文件」（0.4.0）**：第一次打开时可能一个 md 都没有，而此前没有"新建"这条路（缺文件只提示右键→更换文件，那是"打开已有"）。现在顶栏第 2 个图标是「新建待办文件…」（文档+加号 SVG），夹在「更换文件」「打开文件位置」之间、分组竖线左侧（用户要求 ＋ 在竖线左边）；点击走原生另存为，默认名 `待办.md`，默认目录 = 当前文件父目录、文件不存在时用 exe 目录，父目录不存在会一并创建。用户在对话框里指到**已存在**的文件时按"打开已有文件"处理，绝不覆盖。新建成功的文件写入一段示例（`app/ui/starter.js` 的 `starterText`），用示例自己教用法：右键空白处添加分组、鼠标停在行右缘露出加号加待办、点方框勾选、双击打开详情面板改名、Ctrl+Z、自动保存，以及"父任务 + 缩进备注"一对（主列表不渲染备注且子项会折叠，没有这一对没人会发现面板）。示例只是文件内容，此后永不自动改写，用户自己删。缺失状态的提示改为按顶栏按钮序号指路（"第 2 个图标新建 / 第 1 个图标打开已有"），序号在运行时按 `#hdr .hbtn` 顺序算，不写死。同一处顺带修掉一个会毁掉首次引导的 bug：缺失状态下退出会把空内容写盘，于是下次启动"文件已存在"、示例再也不会生成——`exitApp` 现在要 `S.loaded && !S.missingShown` 才写（`refreshFromDisk` 那条同类保护随函数在 0.4.2 删除，§3-16），空白处右键菜单在缺失时只剩「退出」（§3-14：现在只剩「在末尾添加分组」且置灰），`addTodoEnd` 也不再隐式建文件（§3-14：该函数已删除，加待办走行上的加号）。

20. **面板协议一张表、一次显式回执（0.4.2，[#16](https://github.com/zwxdogs/desktop-todo/issues/16)）**：面板与主窗口之间原本有十几个没类型的消息形状（`panel-data` / `panel-req` / `panel-commit` / `panel-hide` / `panel-ready`），名字与载荷全是两窗各自的字符串字面量，加一个面板操作要同时改 switch、处理函数、确认方向三处。现在收进 `app/ui/panelproto.js`：`TABLE` 一处定义每个消息的名字、方向（`to-main` / `to-panel` / 握手用 `both`）、种类（`op` / `notice` / `command`）与载荷字段，`send` 按表编码——缺键、多键、认不出的名字、方向发错都**当场抛错**；收端再做一遍同样的校验，坏消息只记日志、不投给处理函数。两窗共用同一套握手：装监听 → 互发 `hello` → 对端握手前的消息排队（`data` 是「当前内容」不是一次事件，排队时只留最后一份）→ 收到 `hello` 后补发；每声 `hello` 带一个 epoch（标识「哪一次页面加载」）：收到对面第一次 hello 就回一声，同一个 epoch 不重复回（不 ping-pong），换了 epoch 才再回——面板页重载后是个全新对端，主窗口早就是 ready 状态、不会主动再喊，不回这一声的话新面板发的每条消息都会卡在队列里。宿主对象 `window.__TAURI__` 只取一次（Tauri 的 `withGlobalTauri` 把它作为初始化脚本注入，早于任何页面脚本），拿不到就抛错——**面板那端原来每 20ms 轮询 `window.__TAURI__` 的握手整块删除**，两侧代码路径一致。落定从「400 毫秒墙钟兜底」改成显式回执：主窗口发 `flush {id}`，面板回 `receipt {id, ops}`，`ops` 就是面板本来要交的操作（`setText` / `rename`），主窗口照着落；超时只剩一条告警并 `resolve(null)`，正确性不再挂在墙钟上。关面板（✕ / Esc / Alt+F4）、切文件、批量删除、退出都先落定再动手，所以「没落定的编辑不丢」；面板自己的 `✕`/`Esc` 先把内联编辑与标题改名都收成操作交出去、再发 `close`（只收内联编辑会漏掉改了一半的标题），与 Tk `close_panel` 开头就是 `_commit_edits` 同款；主窗口这一侧的 close 路径一律先走一趟落定、不看 `editing` 通知（漏收一条通知就等于丢字，而空回执只值一个往返）。协议端不碰 DOM、不碰清单，只接一个 link（发 / 收）和一张处理函数表，所以能用 `node --test` 直接跑（两头接线上手动投递，22 项；含「面板页重载后主窗口回一声并重推内容」「重载后队列不再卡住」「同 epoch 不重复回」）。

21. **按接缝拆开 Rust 壳：一次贴桌面，五个具名维护步骤（0.4.2，[#17](https://github.com/zwxdogs/desktop-todo/issues/17)）**：`app/src-tauri/src/main.rs` 原本 1638 行、八件事共用一个大巴状态、四十多处各自加锁；贴桌面要调用方按五步顺序组合（顺序的正确性只写在注释里，启动时因此连调两次），每秒一次的 `poll_tick` 一次做五件事却只回一个文件状态。现在按接缝分家，`main.rs` 只剩 4 行进程外壳（`windows_subsystem` + `app::run()`），实现搬进 `lib.rs` 下 16 个模块（不含 `lib.rs` 与 4 行的 `main.rs`），每个模块拥有自己那块状态与顺序：
    - **`win32`**：全程序唯一出现 `unsafe extern` 与 Win32 常量的地方；对外只有语义化窄接口（`pin_bottom` / `at_desktop_level` / `set_toolwindow` / `set_rounded_corners` / `is_iconic` / `has_topmost` / `virtual_screen` / `lock_instance`）。
    - **`dock`**：两态与贴桌面。「贴到桌面」收成一次 `dock::enter(&host, &win, docked)`——里面就是 `apply → show → apply`（首次 ShowWindow 会按建窗时样式重算 exstyle，显示前落的 TOOLWINDOW 会被抹掉，这两次 apply 中间必须夹那次 show）。**启动不再连调两次**：从前是调用方自己 `apply_docked` → `show` → 再 `apply_docked`，现在是接缝里的一句话。切换仍走 `dock::switch`（状态 → 样式 → 托盘勾选 → 广播 → 存盘 → 日志）。
    - **`maintenance`**：轮询五件事各自具名、可单独调——`reanchor`（Win+D 还原 / 重新压底）、`heal_panel`（面板置顶自愈）、`rescue_offscreen`（离屏救援）、`flush_config`（Moved/Resized 攒下的落盘）、`file_state`（唯一有返回值那一步）；`tick` 只是按固定顺序把它们排一遍。
    - **`state`**：共享状态收成一个 `Host` 句柄（进程事实 + 当前文件 + 日志 + 脏标志），命令层与维护层拿到它就用语义化方法说话，看不到锁。状态按所有者分家：模式在 `dock`、看门狗在 `watchdog`、退出在 `exit`、托盘通道在 `tray`、config 在 `config`、文件在 `files`。

22. **行的身份是行锚，不是下标；写盘失败进顶栏提示条（#18，2026-11-14）**：三处会写错数据的缺陷一起修。
    - **编辑/面板锚点**：`app.js` 的编辑态与 `list.js` 的面板锚点原来都存**行下标**，插入、删除、搬块、整份替换之后下标就不成立，提交时把字写到了别人头上（改「丙」时点甲右边的加号插一条 → 字落到乙身上；删掉前面的乙 → 打的字直接没了）。现在两者都存**行锚**（`list.anchorAt` / `indexOfAnchor` / `panelIndex`）：① 行对象本身（`lines.indexOf(row)`，同一次内存里所有块级操作都复用引用，最硬）；② 行对象被换掉时（整份替换、撤销重新 `parseText`）才按「kind + text + 缩进」认领，且必须**建锚时就唯一（`only`）＋现在也唯一**，否则交不出来（-1）——认错比认不出更糟。`remove` / `deleteCompleted` 由模块自己 `killAnchorIn` 明确作废落在被删区间里的锚，不留给按内容去猜。交不出来时调用方丢弃这次编辑并在顶栏提示「这一条已经不在了，刚才改的字没有写进去」。
    - **同一处例外要记住**：`md.moveBlock` 的 `withEnding` 会给「原本是文件末行」的那一行换一个 `{...line}` 副本（补行尾换行），那一行的 ① 当场失效、掉到 ②——`only` 为真时仍能认出，为假时交不出来。
    - **写盘失败可见**：`write_md` 从「失败回 false」改成「失败抛 `Err(原因)`」，`writeText` 不再把它咽掉，原因经清单模块的 `afterSave(ok, n, err)` 进顶栏提示条（`app/ui/notice.js` 是一张纯函数状态机：失败常驻、短消息不许盖住它、成功才收掉、点它重试）。切文件/新建/退出三条「按失败继续」的路径走 `saveQuietly`，其中前两条失败时补一条短消息——那几笔改动随内存替换就真的没了。
    - **顺带修掉的活 bug**：`warn_readonly` 原来把**任何**写失败都当成「程序目录不可写」，磁盘满或目标文件被别的程序占着时弹的是「请把整个文件夹移到可写位置」这个与事实无关的建议。现在只认 `os error 5/13/19`（`files::is_permission_failure`），其余交给提示条。
    - 验证：`node --test app/ui/*.test.js tools/*.test.mjs` **223/223**（新增 `app/ui/list.anchor.test.js` 15 项：插入/删除/搬块后锚仍指自己、同名同缩进各自独立、整份替换后按内容重绑、目标不在或两处同名时交不出来、**同名两条删掉一条之后不许认领幸存的那条**、改名后仍认得回来、面板同款；`app/ui/notice.test.js` 8 项：失败接管/短消息不许盖/过期只清自己/成功只清失败/可点判定；`list.test.js` 新增 1 项：写盘原因要原样传到 `afterSave`），`cargo test --offline` **42/42**（新增 `write_failure_tests` 2 项：权限类认得出来、磁盘满/占用/路径非法不许误判成只读目录）。
