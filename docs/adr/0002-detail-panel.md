# 主列表改摘要视图：子待办与备注收进详情面板

待办的子待办和备注（Markdown 无序列表行）此前全部平铺在主列表里，层级一深主列表就淹没在子项中。决定引入「详情面板」：主列表只显示分组标题、顶层待办和分组直属备注，待办的整个子块（子待办 + 备注）收进一个双击/点徽标打开的 Toplevel 面板，按文件顺序递归混排显示；有内容的待办行右侧显示递归统计徽标（如「✓2/5 📝3」）。

关键约束：**文件格式不变**。层级仍纯缩进表达，备注仍是一行 `- 文本`，无新语法、无 id、无迁移；软件成为唯一编辑器（Obsidian 退出编辑场景），但其他 Markdown 编辑器打开依旧可读可改。

## Considered Options

- **内联折叠（点击展开/收起子块）**：改动最小，但挂件窗口宽度有限，展开后主列表滚动上下文丢失；且无法同时看「一个待办的完整子树 + 主列表」。否决。
- **双行卡片（待办行内直接显示备注摘要）**：每行高度不一致破坏紧凑列表观感，备注多时仍然爆炸。否决。
- **换树控件（ttk.Treeview / 自绘 Canvas 树）**：获得原生折叠，但丢失现有的 Label 行渲染、内联编辑、换行宽度自适应等既有行为，改动面覆盖整个渲染层。否决。
- **详情面板 + 徽标摘要**：主列表保持等高紧凑行；完整子树在独立 Toplevel 里用现有 build_row 交互模式渲染；子块扫描做成纯函数（`subtree_end` / `subtree_stats` / `delete_subtree`）供徽标统计、面板渲染、整树删除三处共用，可用 unittest 覆盖。选中。

## Consequences

- 新增 `subtree_end`（子块边界：空行不打断、块尾空行不算、header 硬截断）、`subtree_stats`（递归统计）、`delete_subtree` 三个模块级纯函数，配套 `test_todo.py` 用例。
- 删除待办的语义从「删一行」变为「删整个子块」，不弹确认框，靠 Ctrl+Z（50 步撤销栈）兜底；删备注仍只删一行。
- 面板是单实例 Toplevel：新开替换旧、跟随外部轮询重载重定位（按「待办文字 + 缩进」作锚）、对应待办被删自动关闭；原文模式与退出时会关闭面板。
- 双击待办从「内联编辑」变为「打开面板」，内联改名保留在右键菜单「编辑」与面板标题双击。
- 渲染仍是全量重建（挂件规模下无性能问题）；面板刷新统一挂在 `render_list` 末尾（主列表是清单渲染的唯一出口），面板编辑与主列表徽标实时联动。
- 已知取舍：面板行渲染（`p_build_row`/`p_edit` 等）与主列表（`build_row`/`edit_row` 等）保持有意同构——两视图交互语义有差异（徽标、菜单、编辑路由），统一成共享行组件留作后续重构；滚轮绑定与换行宽度计算已抽成共用方法（`_bind_wheel_tree`/`_update_wrap_for`）。
- 子块中间的普通段落行（other，解析不出缩进）不打断子块，随其后的子行一起圈进面板；子块边界上夹 other 行的旧文件不会把更深子行漏回主列表。
