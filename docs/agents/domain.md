# 领域文档

工程技能在探索代码库时，如何使用本仓库的领域文档。

## 探索前先读

- 仓库根目录的 **`GLOSSARY.md`**；若根目录有 **`GLOSSARY-MAP.md`**，它指向每个上下文各自的 `GLOSSARY.md`，读与当前主题相关的那些（本仓库是单上下文，没有这个文件）。
- **`docs/adr/`**：读与本次要改的区域相关的 ADR。

这些文件不存在时**静默继续**：不要提示缺失，也不要主动建议创建。`/domain-modeling` 技能会在术语或决策真正确定时按需生成。

## 文件结构

单上下文仓库（本仓库）：

```
/
├── GLOSSARY.md
├── docs/adr/
│   ├── 0001-....md
│   └── 0002-....md
└── ...
```

多上下文仓库（根目录有 `GLOSSARY-MAP.md`）才有每个上下文各自的 `GLOSSARY.md` 与 `docs/adr/`。

## 使用术语表的词汇

输出里提到领域概念（issue 标题、重构方案、假设、测试名）时，用 `GLOSSARY.md` 里定义的词，不要漂移到它明确回避的同义词。

概念不在术语表里时说明两件事之一：你在发明项目不用的词（重新考虑），或确有缺口（记下来交给 `/domain-modeling`）。

## 标出 ADR 冲突

输出与既有 ADR 矛盾时明确说出来，不要默默覆盖：

> _与 ADR-0007（event-sourced orders）冲突，但因为……值得重开。_
